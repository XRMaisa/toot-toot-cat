## 一、專案定位與核心概念

這是一個以**日常化、遊戲化**包裝的 **Web3D / WebXR 互動小遊戲**，表層是可愛搞笑的貓咪房間小遊戲，底層架構 1:1 對應**工業數位孿生（智慧樓宇 HVAC 空調 / 資料中心 DCIM 溫場與氣流模擬）**的技術能力。

| 遊戲元素 | 對應工業數位孿生概念 |
|---|---|
| 貓咪放屁（不同關卡＝不同濃度氣體） | 異常熱源 / 氣體洩漏源 |
| 電風扇、冷氣、開關門窗 | HVAC 空調系統、通風排氣、氣流導引 |
| 電腦主機發熱讓屁往上飄 | 熱對流 / 熱浮力效應（Thermal Buoyancy） |
| 房間 3D 臭味熱力圖 | 3D 溫場 / 氣體濃度體積視覺化（類 CFD 簡化模擬） |
| 人類移動並以鼻子偵測濃度超標 | 移動式感測器（Sensor）座標採樣 ＋ 閾值告警（Alert） |
| 玩家開關家電測試排氣路徑 | IoT 設備雙向控制 ＋ What-if 情境模擬 |
| Q 版微縮房間 ＋ WebXR 切換 | 微縮廠房 / 機房 AR/VR 巡檢視角 |

---

## 二、遊戲玩法與特色

1. **角色與目標**：
   - 玩家扮演房間裡的**貓咪**，在房間裡移動並需要「放屁」排出氣體。
   - 房間裡有**人類**會隨機走動、活動，或躺在床上睡覺。
   - 玩家必須操作房間設備，控制氣流與熱浮力，讓臭氣擴散、往天花板飄或從門窗排出，**不能讓人類鼻子所在位置的臭味濃度超標**，否則會被抓到揍一頓。
2. **關卡設計**：
   - 不同關卡對應**不同濃度的屁**（或不同擴散速度、不同人類活動路線）。
3. **人類嗅覺判定（3 階段）**：
   - `濃度 < 30%`：沒感覺。
   - `30% ～ 70%`：頭上冒「？」開始懷疑、四處張望。
   - `> 70%`：紅色告警「💢」，判定失敗（被揍）。
4. **核心亮點：一鍵切換「遊戲模式 ↔ 工程師（Digital Twin）模式」**：
   - **遊戲模式**：Q 版可愛微縮房間、半透明柔邊臭氣雲朵、生動角色反應。
   - **工程師模式**：房間切為半透明線框，顯示 **3D 彩色熱力圖網格、風向粒子流線、即時濃度折線圖與設備狀態面板**。

## 三、技術棧與架構

- **3D / WebXR 引擎**：**Three.js**（支援桌面 3D 瀏覽，並透過 `renderer.xr.enabled = true` 支援 WebXR；開發期可用 Chrome 擴充套件 `Immersive Web Emulator` 模擬）。
- **外殼與 UI**：**Vue 3 + Vite + Tailwind CSS**（負責 2D 儀表板、模式切換、關卡選單、即時濃度曲線圖）。
- **效能原則**：
  - 遊戲主迴圈（`requestAnimationFrame`）與氣體網格資料存於**純 JS 物件 / TypedArray**，不放進 Vue 的 `ref` / `reactive` 避免響應式卡頓。
  - Vue 儀表板數據採節流更新（例如每 200～500 ms 更新一次）。

## 四、3D 空間網格模擬規格

### 1. 空間尺寸與格子切分
- 對應真實房間大小：約 **寬 4m × 高 2.5m × 深 4m**。
- 網格解析度：**`NX = 16, NY = 10, NZ = 16`**（共 **2,560 格**，每格代表 **25 cm**，並抽成常數方便日後調整）。
- **垂直高度分層（10 層）**：
  - `y = 0～1`：地板、貓咪放屁高度
  - `y = 2～3`：躺在床上的人類鼻子高度
  - `y = 6～7`：站立走動的人類鼻子高度
  - `y = 8～9`：天花板（利用電腦熱浮力引導臭氣的安全區）

### 2. 簡化物理計算（每 50 ms 更新一次）
1. **擴散（Diffusion）**：每格臭味向前後左右上下 6 個非障礙物鄰居平均擴散。
2. **風力推動（Advection）**：電風扇 / 冷氣開啟時，在吹拂範圍的格子賦予風速向量，推移臭味。
3. **熱浮力（Buoyancy）**：
   - 電腦主機發熱區：賦予向上速度（`+Y`），讓臭氣往上飄過床鋪。
   - 冷氣出風口：賦予向下沉降冷風（`-Y`）。
4. **排氣衰減（Exhaust / Decay）**：門或窗戶開啟時，對應邊界格子的濃度快速歸零。

## 五、房間家具、美術與效能規範

### 1. 家具清單與網格佔用（邏輯層標記為 `SOLID` 障礙物）
- **床**（約佔 `2 × 6` 格）
- **書桌**（約佔 `2 × 1` 格）
- **椅子**
- **電腦主機**（可切換待機 / 高負載發熱）
- **冷氣**（可開關）
- **電風扇**（可開關、擺頭方向）
- **門、窗戶**（可開關作為排氣口）

### 2. Mesh 拆分與效能紅線
- **靜態部位合併**：例如床架＋床墊＋枕頭、書桌桌面＋桌腳合併成單一 Mesh。
- **互動/可動部位獨立拆出**：門片、窗扇、電風扇扇葉與風扇頭、電腦主機獨立成小 Mesh 方便旋轉與互動點擊。
- **低 Draw Call 設計**：
  - 3D 臭味熱力圖：用 1 個 `InstancedMesh` 繪製（1 次 Draw Call）。
  - 風向流動箭頭 / 粒子：用 1 個 `InstancedMesh` 繪製（1 次 Draw Call）。
  - 整體房間總 Draw Call 目標控制在 **40～70 次以內**（確保手機與 WebXR 穩跑 72～90 fps）。
- **燈光與貼圖**：
  - 全房間僅 **1 盞主燈開啟陰影**（Shadow Map `1024 × 1024`）。
  - Q 版風格優先使用純色材質或小貼圖（≤ `512 × 512`）。

## 六、建議分階段開發（MVP 路線）

- **Phase 1（核心模擬引擎）**：建立 Vite + Vue 3 + Three.js 專案，做出簡易幾何家具房間、`16×10×16` 臭味擴散／風場／熱浮力模擬、`InstancedMesh` 3D 熱力圖與電風扇／窗戶開關。
- **Phase 2（遊戲迴圈）**：加入 Q 版貓咪移動與放屁技能、人類隨機走動／躺床行為、鼻子座標濃度偵測與 3 階段反應、多濃度關卡。
- **Phase 3（數位孿生面板與 WebXR）**：製作 Vue + Tailwind 右側監控面板（即時濃度曲線、設備控制）、一鍵切換「遊戲模式 ↔ 工程師模式」、串接 Three.js WebXR（桌面微縮 AR / VR 巡檢模式）。
